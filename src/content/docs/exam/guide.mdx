:::tip[한 줄 요약]
전공 필기는 **외우는 문제**(용어·짝 맞추기)와 **계산 문제**(스케줄링·페이지 교체·서브넷 등)로 나뉘어요. 계산 문제는 공식 한두 줄만 알면 매번 같은 방법으로 풀리니, **계산 유형부터 손으로 풀어 보는 것**이 가장 빨리 점수가 오르는 길이에요.
:::

:::note[처음이라면 여기까지]
① 이 섹션의 페이지는 모두 같은 순서예요: 한 줄 요약 → 개념 표 → 단계별 계산 → 객관식 함정 → 연습 문제.

② 아래 **계산 유형 체크리스트** 표를 보고, 각 페이지의 예제를 종이에 직접 따라 풀어 보세요. 눈으로만 읽으면 시험장에서 손이 안 움직여요.

③ 필기 정답은 **수험서 기준**이에요. 실무와 다르게 답해야 하는 곳은 아래 "필기 기준 vs 실무" 표에 모아 뒀어요.

④ 면접 섹션에 같은 개념이 더 쉽게 풀려 있는 경우가 많아요. 막히면 맨 아래 링크로 넘어가 보세요.
:::

## 이 섹션 사용법

필기 페이지는 면접 페이지와 모양이 조금 달라요. 면접 페이지가 "30초 동안 말하기"를 목표로 한다면, 필기 페이지는 "보기 4개 중 하나를 빨리, 정확히 고르기"가 목표예요.

| 블록 | 하는 일 | 공부할 때 |
|---|---|---|
| 한 줄 요약·처음이라면 여기까지 | 그 과목에서 가장 많이 나오는 것 | 시험 전날 이것만 다시 읽기 |
| 개념 정리 | 용어와 비교를 표로 | 표의 **굵은 글씨**가 보기에서 바뀌어 나와요 |
| 단계별 계산 | 계산 유형을 한 단계씩 | 종이에 직접 따라 풀기 |
| 객관식 함정 | 헷갈리는 짝, 틀린 보기 모양 | 문제 풀기 직전에 훑기 |
| 연습 문제 | 4지선다, 쉬운 것 → 어려운 것 | 틀린 번호는 표시해 두고 다음 날 다시 |

"심화:"가 붙은 소제목은 처음엔 건너뛰어도 돼요. 시험에 가끔 나오지만 기본을 다 한 뒤에 봐도 늦지 않아요.

## 계산 유형 체크리스트

필기에서 계산이 나오는 유형을 모았어요. 오른쪽 칸의 공식·요령만 기억하면 나머지는 같은 절차의 반복이에요. 하나씩 풀어 보고 왼쪽에 체크하세요.

| 유형 | 페이지 | 핵심 공식·요령 |
|---|---|---|
| 스케줄링 평균 대기·반환 시간 | [CPU 스케줄링](../os/cpu-scheduling/) | 간트 차트부터 그리기. 반환 = 종료 − 도착, 대기 = 반환 − 실행. HRN 응답률 = (대기 + 실행) ÷ 실행 |
| 페이지 부재 횟수 | [메모리 관리](../os/memory/) | 프레임 칸을 표로 그리고 한 칸씩 채우기. 처음 빈 프레임 채우는 것도 부재로 셈(지문에 "제외"가 없으면) |
| 디스크 헤드 이동 거리 | [디스크 스케줄링](../os/disk-file/) | 처리 순서를 먼저 쓰고 이웃끼리 차이의 합. 처음 **방향**, 트랙 범위, C-SCAN 되돌아가는 거리 포함 여부 확인 |
| 은행원 알고리즘 안전 순서 | [동기화와 교착상태](../os/sync-deadlock/) | Need = Max − Allocation. Need가 Available 이하인 프로세스를 끝내고 그 Allocation을 Available에 더하기를 반복 |
| 서브넷 계산 | [IP 주소와 서브넷](../network/ip-subnet/) | 호스트 비트 h = 32 − 프리픽스. 호스트 수 = 2^h − 2. 블록 크기 = 256 − (마지막 0 아닌 마스크 옥텟) |
| 해밍 코드 | [데이터 통신 기초](../network/data-comm/) | 패리티는 1·2·4·8… 자리. 받은 쪽에서 틀린 패리티 번호를 더하면 오류 비트 위치 |
| 섀넌 용량 | [데이터 통신 기초](../network/data-comm/) | C = B · log2(1 + S/N). S/N이 dB면 먼저 배수로: 10^(dB ÷ 10) |
| 후위 표기 변환·계산 | [스택·큐·연결 리스트](../ds/linear/) | 변환: 연산 순서대로 괄호를 치고 연산자를 닫는 괄호 자리로. 계산: 숫자는 push, 연산자가 오면 두 개 pop |
| 트리 순회 | [트리·이진 탐색 트리·힙](../ds/tree/) | 전위 = 루트·왼·오, 중위 = 왼·루트·오, 후위 = 왼·오·루트. 서브트리마다 같은 규칙을 다시 적용 |
| 정렬 n회전 결과 | [정렬·탐색·해싱](../ds/sort-search/) | 버블 1회전 = 최댓값이 맨 뒤로. 선택 1회전 = 최솟값이 맨 앞으로. 삽입 k회전 = 앞 k+1개가 정렬됨 |
| 해싱 충돌 해결 | [정렬·탐색·해싱](../ds/sort-search/) | 주소 = 키 mod 테이블 크기. 선형 조사는 다음 칸으로 한 칸씩, 체이닝은 같은 칸에 리스트로 매달기 |
| 관계 대수 결과 | [관계 모델·키·관계 대수](../db/relational/) | σ는 행을, π는 열을 고름(π는 중복 제거). 카티션 프로덕트의 차수 = 더하기, 카디널리티 = 곱하기 |
| 체크포인트 REDO·UNDO | [트랜잭션·회복·병행 제어](../db/transaction-recovery/) | 체크포인트 뒤 ~ 장애 전에 커밋 = REDO, 장애 때까지 커밋 없음 = UNDO, 체크포인트 전에 커밋 = 할 일 없음 |
| PERT·CPM 일정 | [SW 생명주기](../se/lifecycle/) | CPM 임계 경로 = 시작부터 끝까지 **가장 긴** 경로. PERT 기대 시간 = (낙관 + 4 × 최빈 + 비관) ÷ 6 |
| 순환 복잡도 | [소프트웨어 테스트](../se/testing/) | V(G) = 간선 수 − 노드 수 + 2. 판단(분기) 노드 수 + 1, 닫힌 영역 수 + 1로도 같은 값 |
| IEEE 754 변환 | [데이터 표현](../arch/data-representation/) | 2진수로 바꿔 1.xxx × 2^e 꼴로 정규화. 단정밀도 지수 칸 = e + 127, 가수 칸엔 맨 앞 1을 빼고 저장 |

:::caution[계산 문제에서 자주 잃는 점수]
- **조건 한 줄을 놓치는 실수**가 계산 실수보다 많아요. 시작 방향, 시간 할당량, 초기 적재를 부재로 세는지, 서브넷 0을 쓰는지 같은 조건에 먼저 밑줄을 치세요.
- 답을 구하면 보기 숫자와 바로 맞춰 보세요. 보기에 내 답이 없으면 조건을 다르게 읽었을 가능성이 커요. 그때는 다른 해석으로 한 번 더 풀어 보세요.
:::

## 공부 순서 제안

정해진 정답은 없어요. 다만 전공 지식이 거의 없는 상태라면 아래 순서가 효율적이에요.

1. **계산 유형 먼저 손으로 풀기.** 위 체크리스트의 페이지를 열어 "단계별 계산"만 종이에 따라 풀어요. 계산은 규칙이 정해져 있어서 한 번 손에 익으면 잘 안 잊어요.
2. **"처음이라면 여기까지"와 개념 표 읽기.** 과목별로 한 번씩 훑어요. 다 외우려 하지 말고, 표에서 **굵은 글씨**만 눈에 익혀요.
3. **객관식 함정 표 보기.** "A는 B다"가 아니라 "A와 B가 헷갈린다"로 정리된 표예요. 시험 보기는 대부분 이 짝을 살짝 바꿔서 만들어요.
4. **연습 문제 풀기.** 쉬운 것부터 순서대로 풀고, 틀린 문제는 해설을 읽은 뒤 해당 개념 표로 돌아가요.
5. **틀린 것만 다시.** 다음 날 틀린 번호만 다시 풀어요. 두 번 연속 맞히면 넘어가요.

과목 순서는 서로 이어지는 쪽으로 가면 덜 헷갈려요. 예를 들어 [트리](../ds/tree/) → [그래프](../ds/graph/)(다익스트라) → [라우팅](../network/routing-transport/)(OSPF가 다익스트라를 써요), [동기화와 교착상태](../os/sync-deadlock/) → [트랜잭션·병행 제어](../db/transaction-recovery/)(2PL과 교착)처럼요.

## 필기 기준 vs 실무

필기 정답은 수험서 기준이라 실제 제품·표준 문서와 다르게 답해야 하는 곳이 있어요. 면접에서는 실무 쪽으로, 필기 보기에서는 수험서 쪽으로 답하세요.

| 주제 | 필기 정답 기준 | 실무·표준 문서 | 페이지 |
|---|---|---|---|
| GRANT·REVOKE 분류 | **DCL** | Oracle 문서는 DDL로 분류 | [DB 설계·SQL 분류](../db/design-sql/) |
| COMMIT·ROLLBACK 분류 | 보기에 TCL이 없으면 **DCL** | 트랜잭션 제어(TCL)로 따로 분류 | [DB 설계·SQL 분류](../db/design-sql/) |
| 뷰 정의 변경 | **ALTER 불가**, DROP 후 재생성 | `CREATE OR REPLACE VIEW`, MySQL은 `ALTER VIEW`도 지원 | [DB 설계·SQL 분류](../db/design-sql/) |
| 회복 기법 | 즉시 갱신·지연 갱신·그림자 페이징을 나눠서 외움 | InnoDB는 redo·undo 로그를 둘 다 쓰는 WAL 방식이라 즉시 갱신에 가까움 | [트랜잭션·회복](../db/transaction-recovery/) |
| 재해싱 | 이중 해싱을 "재해싱"이라고도 부름 | rehash는 보통 테이블을 키우고 모든 키를 다시 넣는 것 | [정렬·탐색·해싱](../ds/sort-search/) |
| 버블 정렬 최선 | 조기 종료 없는 기준이라 O(n²) | 교환이 없으면 멈추게 하면 O(n) | [정렬·탐색·해싱](../ds/sort-search/) |
| 서브넷 개수 | 옛 규칙의 2^n − 2가 교재에 남아 있음 | 지금은 2^n(서브넷 0도 사용). 조건이 없으면 2^n | [IP 주소와 서브넷](../network/ip-subnet/) |
| ARP 계층 | 교재 기준 3계층 | RFC는 링크 계층 장에서 다룸 | [OSI 7계층](../network/osi-tcpip/) |
| 피터슨 알고리즘 | 올바른 상호 배제 해법 | 명령 재배치 때문에 메모리 배리어 없이는 깨질 수 있음 | [동기화와 교착상태](../os/sync-deadlock/) |
| 검증과 확인 | 검증(verification) = 명세대로 **제대로 만들었나**, 확인(validation) = 사용자가 원하는 **제대로 된 것을 만들었나** | 현업에선 두 단어를 섞어 쓰는 일이 많음. 한국어 이름을 반대로 붙인 수험서도 있으니 영어로 외우기 | [소프트웨어 테스트](../se/testing/) |
