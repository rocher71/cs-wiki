필기 네트워크 문제는 **계층 ↔ 기능 ↔ PDU ↔ 장비 ↔ 프로토콜** 짝 맞추기가 절반이에요. 여기에 **IPv4 헤더 필드**, **IPv6 특징**(128비트, 브로드캐스트 없음, 체크섬 없음), **ARP(IP→MAC)·RARP(MAC→IP)·ICMP(오류 보고)·IGMP(멀티캐스트 그룹)** 구분을 더하면 돼요.
:::

:::note[처음이라면 여기까지]
① 아래부터 물리·데이터 링크·네트워크·전송·세션·표현·응용, "물데네전세표응"으로 외워요.

② 단위(PDU)는 아래부터 비트 → 프레임 → 패킷 → 세그먼트 → 메시지예요.

③ 장비는 리피터·허브(1층), 브리지·스위치(2층), 라우터(3층)예요.

④ ARP는 IP로 MAC을 찾고, RARP는 그 반대예요. 방향을 바꾼 보기가 단골 함정이에요.
:::

## 쉽게 이해하기

택배를 보낸다고 생각해 봐요. 물건(데이터)을 상자에 넣고, 받는 사람 이름표(포트)를 붙이고, 주소 송장(IP)을 붙이고, 지금 실을 트럭 번호(MAC)를 붙여요. 층마다 자기 일에 필요한 정보만 하나씩 덧붙이는 셈이에요. 이걸 **캡슐화**(encapsulation, 위에서 아래로 내려가며 헤더를 붙이는 것)라고 해요.

받는 쪽은 바깥 포장부터 벗겨요. 트럭 번호 확인 → 주소 확인 → 이름표 확인 → 물건 꺼내기 순서예요.

단, 실제로는 중간 물류센터(라우터)를 지날 때마다 트럭 번호(MAC)는 바뀌고, 주소 송장(IP)은 그대로 가요(NAT 제외).

개념 설명과 기본 그림은 [네트워크 계층 (OSI 7계층·TCP/IP 4계층)](../../../web/network-layers/)에 있어요. 이 페이지는 **시험용 암기 표와 함정**에 집중해요.

## 개념 정리

### OSI 7계층 암기 표

**OSI 참조 모델**(ISO 7498)은 서로 다른 시스템이 통신할 수 있게 역할을 7층으로 나눈 기준 모델이에요. 각 층은 상대편의 같은 층과만 대화하고, 바로 위층에 서비스를 제공해요.

| 계층 | 핵심 기능(객관식 키워드) | PDU | 장비 | 대표 프로토콜 |
|---|---|---|---|---|
| 7 응용 | 사용자 인터페이스, 가상 터미널, 파일 전송, 메일, 디렉터리 | 메시지 | 게이트웨이, L7 스위치 | HTTP, FTP, SMTP, POP3, IMAP, DNS, Telnet, SSH, SNMP, DHCP |
| 6 표현 | 코드·형식 변환, 암호화·복호화, 압축 | 메시지 | - | JPEG, MPEG, ASCII, EBCDIC |
| 5 세션 | 세션 설정·유지·종료, 대화 제어(반이중/전이중), 동기화(체크포인트) | 메시지 | - | NetBIOS, RPC |
| 4 전송 | 종단 간 신뢰성, 포트 주소, 분할·재조립, 흐름·오류·혼잡 제어 | 세그먼트(TCP), 데이터그램(UDP) | L4 스위치 | TCP, UDP, SCTP |
| 3 네트워크 | 출발지→목적지 패킷 전달, 논리 주소(IP), 라우팅, 단편화 | 패킷 | 라우터, L3 스위치 | IP, ICMP, IGMP, ARP·RARP(교재 기준), RIP, OSPF, BGP |
| 2 데이터 링크 | 옆 노드까지 전달, 프레임 구성, 물리 주소(MAC), 흐름·오류 제어, 매체 접근 제어 | 프레임 | 브리지, 스위치 | Ethernet(802.3), Wi-Fi(802.11), HDLC, PPP |
| 1 물리 | 비트를 전기·빛 신호로, 커넥터·케이블 규격 | 비트 | 리피터, 허브, 케이블 | RS-232, V.24, X.21 |

장비 분류는 교재마다 조금 달라요. 그냥 "스위치"라고 하면 2계층(L2)이지만, 라우팅까지 하는 L3 스위치나 포트·내용을 보는 L4·L7 스위치도 있어요. 게이트웨이도 "프로토콜이 다른 망을 잇는 장비"라서 여러 계층에 걸친다고 보는 교재가 있어요. 문제에 따로 단서가 없으면 스위치는 2계층, 게이트웨이는 7계층으로 골라요.

**전달 범위**도 자주 물어요.

| 계층 | 범위 | 쓰는 주소 |
|---|---|---|
| 2 데이터 링크 | 노드 ↔ 바로 옆 노드 (hop-to-hop) | MAC (48비트, 홉마다 바뀜) |
| 3 네트워크 | 출발 호스트 ↔ 목적 호스트 | IP (IPv4 32비트, 가는 동안 유지) |
| 4 전송 | 프로세스 ↔ 프로세스 (end-to-end) | 포트 (16비트, 0~65535) |

### TCP/IP 4계층과 OSI 대응

실제 인터넷은 **TCP/IP 모델**로 돌아가요. 표준(RFC 1122)은 4계층이에요.

| TCP/IP 4계층 | OSI 대응 | 대표 프로토콜 |
|---|---|---|
| 응용 | 5·6·7 | HTTP, DNS, SMTP, FTP |
| 전송 | 4 | TCP, UDP |
| 인터넷 | 3 | IP, ICMP, IGMP |
| 링크(네트워크 인터페이스) | 1·2 | Ethernet, Wi-Fi, ARP(RFC 기준) |

교재에 따라 물리를 따로 떼어 5계층으로 그리기도 해요. 문제에 "4계층"이라고 나오면 링크·인터넷·전송·응용이 답이에요.

TCP와 UDP의 차이(연결형·신뢰성 vs 비연결형·빠름, 헤더 20바이트 vs 8바이트)는 [TCP와 UDP](../../../web/tcp-udp/)에서 자세히 봐요.

### IPv4 헤더 주요 필드

옵션이 없으면 **20바이트**, 옵션을 넣으면 최대 **60바이트**예요(RFC 791).

| 필드 | 비트 | 시험 포인트 |
|---|---|---|
| Version | 4 | IPv4면 4 |
| IHL (헤더 길이) | 4 | **32비트(4바이트) 단위**. 5 → 20바이트, 15 → 60바이트 |
| Type of Service | 8 | 서비스 품질. 지금은 DSCP·ECN으로 씀 |
| Total Length | 16 | 헤더+데이터 전체 길이, 최대 65,535바이트 |
| Identification | 16 | 같은 원본에서 나온 조각끼리 같은 값 |
| Flags | 3 | 예약·**DF**(쪼개지 마)·**MF**(뒤에 조각 더 있음) |
| Fragment Offset | 13 | 원본에서 조각 위치, **8바이트 단위** |
| TTL | 8 | 라우터를 지날 때마다 1 감소, 0이면 버리고 ICMP로 알림 |
| Protocol | 8 | 위에 실린 것: ICMP = 1, IGMP = 2, TCP = 6, UDP = 17 |
| Header Checksum | 16 | **헤더만** 검사(데이터는 안 봄) |
| Source / Destination Address | 32 / 32 | 출발지·목적지 IP |

- **TTL**(Time To Live): 정의상 단위는 초지만, 실제로는 거친 라우터 수(홉 수)처럼 동작해요. 패킷이 길을 잃고 끝없이 도는 것을 막아요. traceroute가 이걸 이용해요.
- **단편화**(fragmentation, 큰 패킷을 링크가 받을 수 있는 크기(MTU)로 쪼개는 것): IPv4에서는 중간 라우터도 쪼갤 수 있고, **다시 합치는 건 최종 목적지만** 해요. DF = 1이면 쪼개지 않고 버린 뒤 ICMP로 알려요.

### IPv6 특징 (RFC 8200)

| 항목 | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | 32비트 | **128비트** (16비트씩 8그룹, 16진수, 콜론 구분) |
| 기본 헤더 | 20~60바이트(가변) | **40바이트 고정** + 확장 헤더 |
| 헤더 체크섬 | 있음 | **없음** |
| 단편화 | 출발지·중간 라우터 | **출발지만** (Fragment 확장 헤더) |
| 수명 필드 | TTL | Hop Limit |
| 상위 프로토콜 필드 | Protocol | Next Header |
| 주소 종류 | 유니캐스트·멀티캐스트·브로드캐스트 | 유니캐스트·멀티캐스트·**애니캐스트** (**브로드캐스트 없음**) |
| IP→MAC 찾기 | ARP | ICMPv6 기반 NDP(이웃 탐색) |
| 기타 | - | Flow Label(QoS), 자동 주소 설정(SLAAC), 최소 MTU 1280바이트 |

- **애니캐스트**(anycast): 같은 주소를 가진 여러 노드 중 가장 가까운 하나에게 보내요.
- 표기 축약: 각 그룹 앞자리 0은 생략할 수 있고, 0만 있는 그룹이 이어지면 `::`로 **한 번만** 줄여요. 예: 2001:0db8:0000:0000:0000:0000:0000:0001 → `2001:db8::1` (2001:db8::/32는 문서용 대역)
- IPv4에서 IPv6로 넘어가는 방법: **듀얼 스택**(둘 다 켜기), **터널링**(IPv6를 IPv4에 싸서 보내기), **주소 변환**(NAT64 등).

### ARP · RARP · ICMP · IGMP

넷 다 교재에서 네트워크(3) 계층 쪽 프로토콜로 묶어요.

| 프로토콜 | 하는 일 | 기억할 점 |
|---|---|---|
| **ARP** (RFC 826) | **IP → MAC** | 같은 네트워크에 브로드캐스트로 "이 IP 누구?" → 주인만 유니캐스트로 답 → ARP 캐시에 저장. 목적지가 다른 네트워크면 게이트웨이의 MAC을 찾아요 |
| **RARP** (RFC 903) | **MAC → IP** | 디스크 없는 장비가 자기 IP를 알아낼 때. 지금은 BOOTP·DHCP로 대체 |
| **ICMP** (RFC 792) | 오류 보고·진단 | 목적지 도달 불가, 시간 초과, 에코 요청/응답. ping·traceroute가 씀. **알리기만 하고 고치지 않아요**. IP 위에 실리지만(Protocol = 1) 3계층 |
| **IGMP** (RFC 3376) | 멀티캐스트 그룹 가입·탈퇴 | 호스트와 가까운 라우터 사이. IPTV 같은 그룹 전송. IPv6에서는 MLD가 대신 |

### 심화: ARP는 몇 계층인가

교재는 ARP를 네트워크(3) 계층 기능으로 넣고, 그림에서는 "2.5계층"으로 그리기도 해요. RFC 1122는 링크 계층 장에서 다뤄요. 객관식에서는 계층보다 **방향**(ARP = IP→MAC)이 훨씬 자주 함정으로 나와요. "ARP는 MAC 주소로 IP를 알아낸다"는 틀린 보기예요. 계층을 꼭 골라야 하면 교재 기준인 3계층을 골라요.

## 계산 예제

### 예제 1: IHL 값으로 헤더 길이 구하기

IHL은 4바이트 단위라서 **헤더 길이 = IHL × 4바이트**예요.

1. IHL = 5 → 5 × 4 = **20바이트**(옵션 없음, 최소)
2. IHL = 15 → 15 × 4 = **60바이트**(4비트 최댓값, 최대)
3. IHL = 8 → 32바이트, 옵션이 32 − 20 = **12바이트** 붙어 있어요.

### 예제 2: IPv4 단편화 — 4,000바이트 패킷을 MTU 1,500 링크로

전체 4,000바이트(헤더 20 + 데이터 3,980)인 패킷이 MTU 1,500바이트 링크를 만나요. 옵션은 없어요.

1. **조각 하나에 실을 수 있는 데이터**: 1,500 − 20(헤더) = 1,480바이트. 8의 배수인지 확인해요(1,480 ÷ 8 = 185, 맞아요). Offset이 8바이트 단위라 조각 데이터는 마지막 조각 말고는 8의 배수여야 해요.
2. **나누기**: 3,980 = 1,480 + 1,480 + 1,020 → 조각 3개.
3. **Offset 계산**(앞 조각 데이터 합 ÷ 8):

| 조각 | 데이터 길이 | Total Length | Fragment Offset | MF |
|---|---|---|---|---|
| 1 | 1,480 | 1,500 | 0 ÷ 8 = 0 | 1 |
| 2 | 1,480 | 1,500 | 1,480 ÷ 8 = 185 | 1 |
| 3 | 1,020 | 1,040 | 2,960 ÷ 8 = 370 | 0 |

4. **확인**: 세 조각의 Identification은 모두 같아요. 마지막 조각만 MF = 0이에요. 합치는 건 목적지 호스트가 해요.

## 객관식 함정

| 이렇게 나오면 | 왜 틀렸나 / 맞는 답 |
|---|---|
| "ARP는 MAC 주소로 IP 주소를 알아낸다" | 방향이 반대. ARP = IP→MAC, **RARP = MAC→IP** |
| "암호화·압축은 응용 계층, 가상 터미널은 표현 계층" | 반대로 바꿔 놓은 보기. 암호화·압축·변환 = **표현(6)**, 가상 터미널·파일 전송 = **응용(7)** |
| "대화 제어와 동기점(체크포인트)은 전송 계층" | **세션(5)** 기능 |
| "흐름 제어는 전송 계층에만 있다" | **데이터 링크(2)도 해요**(홉 단위). 전송 계층은 종단 단위. 혼잡 제어는 전송 계층 |
| "허브·리피터는 2계층, 스위치는 1계층" | 리피터·(더미) 허브 = **1**, 브리지·스위치 = **2**, 라우터 = **3** |
| PDU 짝: "3계층 = 세그먼트" | 2 프레임, **3 패킷**, 4 세그먼트 |
| "ICMP는 IP 위에 실리니까 전송 계층" | 실리는 위치와 상관없이 **3계층** |
| "DNS·DHCP는 UDP를 쓰니 전송 계층" | 둘 다 **응용(7)** 프로토콜 |
| "HDLC·PPP는 네트워크 계층" | **데이터 링크(2)** |
| "IPv4 헤더 체크섬은 데이터까지 검사" | **헤더만** 검사 |
| "IPv6는 브로드캐스트를 지원한다" | IPv6엔 **브로드캐스트가 없어요**. 멀티캐스트로 대신 |
| "IPv6 헤더는 128비트" | 128비트는 **주소** 길이. 기본 헤더는 **40바이트** |
| "IPv6도 중간 라우터가 단편화한다" | IPv6는 **출발지만** 단편화 |
| `2001:db8::0::1` 같은 축약 | `::`는 **한 번만** 쓸 수 있어요 |
| "TCP/IP는 7계층" | 표준은 **4계층**(링크·인터넷·전송·응용) |
| "헤더와 트레일러를 둘 다 붙이는 건 물리 계층" | 트레일러(FCS)까지 붙이는 건 **데이터 링크(2)** |

<summary>1. 계층과 장비의 짝이 잘못된 것은? ① 리피터 – 물리 계층 ② 브리지 – 데이터 링크 계층 ③ 라우터 – 네트워크 계층 ④ 더미 허브 – 네트워크 계층</summary>

**정답: ④**

더미 허브는 신호를 그대로 모든 포트로 퍼뜨리기만 해서 **물리(1) 계층** 장비예요. 주소를 보고 길을 고르는 라우터가 네트워크 계층이에요.
</details>

<details>
<summary>2. OSI 표현 계층의 기능으로 알맞은 것은? ① 대화 제어와 동기점 설정 ② 데이터 암호화와 압축 ③ 경로 선택(라우팅) ④ 프레임 오류 검출</summary>

**정답: ②**

표현 계층은 데이터의 형식을 다뤄요. 코드 변환·암호화·압축이 표현 계층이에요. ①은 세션, ③은 네트워크, ④는 데이터 링크 계층이에요.
</details>

<details>
<summary>3. 전송 계층에서 TCP가 다루는 데이터 단위(PDU)는? ① 비트 ② 프레임 ③ 패킷 ④ 세그먼트</summary>

**정답: ④**

아래부터 비트(1) → 프레임(2) → 패킷(3) → 세그먼트(4) → 메시지(5~7)예요. UDP는 같은 4계층이지만 데이터그램이라고 불러요.
</details>

<details>
<summary>4. ARP에 대한 설명으로 옳은 것은? ① MAC 주소로 IP 주소를 알아낸다 ② 목적지의 MAC 주소를 찾기 위해 요청을 브로드캐스트한다 ③ 멀티캐스트 그룹 가입을 관리한다 ④ 전송 중 오류를 발신지에 보고한다</summary>

**정답: ②**

ARP는 같은 네트워크 전체에 "이 IP를 가진 장비의 MAC이 뭐예요?"라고 브로드캐스트로 물어요. ①은 RARP, ③은 IGMP, ④는 ICMP예요.
</details>

<details>
<summary>5. ICMP에 대한 설명으로 틀린 것은? ① ping은 ICMP 에코 요청과 응답을 쓴다 ② traceroute는 TTL 초과 메시지를 이용한다 ③ IP 헤더의 Protocol 값 1로 구분된다 ④ 오류를 발견하면 해당 패킷을 직접 고쳐 다시 보낸다</summary>

**정답: ④**

ICMP는 오류를 **알리기만** 하고 고치거나 다시 보내지 않아요. 재전송은 TCP 같은 위 계층이 맡아요.
</details>

<details>
<summary>6. IPv4 헤더의 IHL 필드 값이 6일 때 헤더 길이와 옵션 길이는? ① 6바이트, 옵션 없음 ② 24바이트, 옵션 4바이트 ③ 48바이트, 옵션 28바이트 ④ 24바이트, 옵션 없음</summary>

**정답: ②**

IHL은 4바이트 단위라 6 × 4 = 24바이트예요. 기본 헤더 20바이트를 빼면 옵션은 4바이트예요.
</details>

<details>
<summary>7. IPv6에 대한 설명으로 틀린 것은? ① 주소는 128비트이다 ② 기본 헤더는 40바이트로 고정이다 ③ 브로드캐스트 주소로 같은 네트워크 전체에 보낼 수 있다 ④ 헤더 체크섬 필드가 없다</summary>

**정답: ③**

IPv6 주소 종류는 유니캐스트·멀티캐스트·애니캐스트 셋이고 브로드캐스트는 없어요. 전체에 보낼 일은 멀티캐스트로 해요.
</details>

<details>
<summary>8. 2001:0db8:0000:0000:0000:0000:0000:0001을 올바르게 줄인 것은? ① 2001:db8::1 ② 2001:db8:::1 ③ 2001:db8::0::1 ④ 21:db8::1</summary>

**정답: ①**

앞자리 0을 빼고(0db8 → db8), 0만 있는 그룹 6개를 `::` 하나로 줄여요. ②는 콜론이 세 개라 형식 오류, ③은 `::`를 두 번 써서 어디가 몇 그룹인지 알 수 없어요. ④는 2001의 뒷자리 0을 지웠는데, 생략할 수 있는 건 **앞자리 0**뿐이에요.
</details>

## 면접 질문

<details>
<summary>Q. OSI 7계층은 무엇이고, 왜 계층을 나누나요?</summary>

**답변(30초)** OSI 7계층은 네트워크 통신을 물리부터 응용까지 일곱 역할로 나눈 참조 모델이에요. 각 층은 바로 아래층이 주는 서비스만 믿고 자기 일만 해서, 한 층을 바꿔도 다른 층은 그대로 둘 수 있어요. 예를 들어 유선을 Wi-Fi로 바꿔도 HTTP 코드는 안 바뀌어요. 실제 인터넷은 이를 네 층으로 묶은 TCP/IP 모델로 동작해요.

**꼬리질문**
- Q. 라우터를 지날 때 바뀌는 주소와 안 바뀌는 주소는? → MAC은 홉마다 바뀌고, IP는 출발지·목적지 그대로예요(NAT 제외).
- Q. IPv6가 IPv4와 크게 다른 점은? → 주소가 128비트로 길어졌고, 헤더가 40바이트로 고정되고 체크섬이 빠졌으며, 브로드캐스트가 없어요.
</details>
