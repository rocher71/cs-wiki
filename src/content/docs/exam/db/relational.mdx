:::tip[한 줄 요약]
릴레이션은 **열 = 속성(개수는 차수)**, **행 = 투플(개수는 카디널리티)**인 표예요. 후보키는 **유일성 + 최소성**, 슈퍼키는 유일성만 갖고, 관계 대수에서 **σ는 행을 고르고 π는 열을 골라요**.
:::

:::note[처음이라면 여기까지]
① 관계 데이터베이스의 표 하나를 **릴레이션**이라 불러요. 열의 개수가 **차수**, 행의 개수가 **카디널리티**예요.

② **키**는 행 하나를 콕 집어 낼 수 있는 열(또는 열 묶음)이에요. 꼭 필요한 열만 쓴 키가 **후보키**, 그중 대표로 고른 게 **기본키**예요.

③ 관계 대수는 표를 넣으면 표가 나오는 계산이에요. σ(시그마)는 조건에 맞는 **행**만, π(파이)는 원하는 **열**만 남겨요.

④ 아래 "단계별 계산"을 따라 하고 연습 문제 1~5번부터 풀어 보세요. "심화:"는 나중에 읽어도 돼요.
:::

## 쉽게 이해하기

학원 출석부를 떠올려 보세요. 맨 위 칸에 "학번·이름·학과·학년"이 적혀 있고, 아래로 학생 한 명이 한 줄씩 채워져 있어요. 이 출석부 한 장이 **릴레이션**, 맨 위 칸 하나하나가 **속성**, 학생 한 줄이 **투플**이에요.

이름만으로는 동명이인이 있어서 학생을 정확히 못 찾아요. 학번은 겹치지 않으니 학번으로 찾으면 돼요. 이렇게 한 줄을 정확히 집어 주는 열이 **키**예요.

관계 대수는 출석부에 연필로 표시하는 방법이에요. "컴공 학생만 동그라미"(σ), "학번·이름 칸만 남기고 가리기"(π), "수강 신청표와 학번끼리 이어 붙이기"(⋈)처럼요.

단, 실제 릴레이션은 종이 출석부와 달리 **줄 순서와 칸 순서에 의미가 없고**, 똑같은 줄이 두 번 나올 수 없어요.

## 제대로 알기

### 릴레이션 용어

| 용어 | 같은 말 | 뜻 |
|---|---|---|
| **릴레이션**(relation) | 테이블, 파일 | 한 대상의 데이터를 담은 2차원 표 |
| **속성**(attribute) | 열, 필드 | 표의 세로 칸 하나 |
| **투플**(tuple) | 행, 레코드 | 표의 가로줄 하나 |
| **차수**(degree) | | 속성(열)의 **개수** |
| **카디널리티**(cardinality) | | 투플(행)의 **개수** |
| **도메인**(domain) | | 한 속성이 가질 수 있는 값 전체의 집합. 보통 데이터 타입으로 정해요 |
| **널**(NULL) | | 아직 모르거나 해당 없는 값. 0이나 공백과 달라요 |

예를 들어 열 6개, 행 4개인 고객 표는 **차수 6, 카디널리티 4**예요.

| 구분 | 다른 이름 | 성질 | 뜻 |
|---|---|---|---|
| **릴레이션 스키마** | 내포(intension) | 정적(잘 안 바뀜) | 릴레이션 이름 + 속성 이름들. 표의 머리줄 |
| **릴레이션 인스턴스** | 외연(extension) | 동적(계속 바뀜) | 어느 순간에 들어 있는 투플들 |

### 릴레이션의 특성 4가지

| 특성 | 뜻 |
|---|---|
| 투플의 **유일성** | 똑같은 투플이 두 개 있을 수 없어요 |
| 투플의 **무순서** | 행의 위아래 순서에는 의미가 없어요 |
| 속성의 **무순서** | 열의 좌우 순서에도 의미가 없어요 |
| 속성의 **원자성** | 칸 하나에는 값 하나만(여러 값을 묶어 넣을 수 없음). 1정규형과 연결돼요 |

표준 교재는 여기에 "한 릴레이션 안에서 속성 이름은 겹치지 않는다", "각 속성 값은 그 속성의 도메인에서 온다"를 덧붙여 설명해요.

### 키의 종류

키를 가르는 성질은 두 가지예요.

- **유일성**: 이 열(묶음)의 값이 모든 투플에서 서로 달라요.
- **최소성**: 꼭 필요한 열만 들어 있어요. 하나라도 빼면 유일성이 깨져요.

예제 표로 확인해 볼게요.

| 학번 | 주민번호 | 이름 | 학과 |
|---|---|---|---|
| S1 | 901 | 김 | 컴공 |
| S2 | 902 | 이 | 경영 |
| S3 | 903 | 김 | 컴공 |
| S4 | 904 | 최 | 수학 |

- 이름은 "김"이 두 번, 학과는 "컴공"이 두 번 나와서 혼자서는 키가 못 돼요.
- 학번, 주민번호는 각각 혼자서 모든 행이 달라요 → 유일성 + 최소성 → **후보키**.
- (학번, 이름)도 모든 행이 다르지만, 이름을 빼도 학번만으로 유일해요 → 최소성 위반 → **슈퍼키**일 뿐이에요.

| 키 | 유일성 | 최소성 | 예제에서 |
|---|---|---|---|
| **슈퍼키**(super key) | O | X(상관없음) | 학번, 주민번호, (학번, 이름), (주민번호, 학과) … |
| **후보키**(candidate key) | O | O | 학번, 주민번호 |
| **기본키**(primary key) | O | O | 후보키 중 고른 하나 → 학번 |
| **대체키**(alternate key) | O | O | 기본키로 안 뽑힌 후보키 → 주민번호 |
| **외래키**(foreign key) | | | 다른(또는 같은) 릴레이션의 기본키를 가리키는 속성 |

- 포함 관계: 후보키는 모두 슈퍼키예요(후보키 ⊂ 슈퍼키). 기본키 + 대체키 = 후보키.
- 후보키를 찾는 순서: 열 하나씩 중복을 확인 → 중복 있는 열은 둘씩 묶어 확인 → 유일한 묶음 중 **더 작은 묶음이 이미 유일하지 않은 것**만 후보키.

### 외래키 규칙

| 규칙 | 내용 |
|---|---|
| 이름 | 참조하는 기본키와 **달라도 돼요** |
| 도메인 | 참조하는 기본키와 **같아야 해요** |
| 개수 | 한 릴레이션에 여러 개 있을 수 있어요 |
| 기본키와의 관계 | 외래키가 기본키의 일부가 될 수도 있어요 |
| 자기 참조 | 자기 릴레이션의 기본키를 가리켜도 돼요(예: 고객 표의 "추천한 고객" 열) |
| NULL | **허용**돼요(아직 정해지지 않은 참조) |

SQL에서 대체키에 UNIQUE를 걸면 값은 겹치지 않지만 NULL은 허용돼요. 기본키는 NULL이 안 돼요.

### 무결성 제약조건

**무결성**(integrity)은 "DB에 틀린 값이 들어가지 않게 지키는 규칙"이에요.

| 종류 | 규칙 | 위반 예 |
|---|---|---|
| **개체 무결성** | 기본키를 이루는 속성은 NULL이 될 수 없고 중복도 안 됨 | 학번 없이 학생을 넣음, 신입 학번이 기존 학번과 같음 |
| **참조 무결성** | 외래키 값은 참조하는 표의 기본키에 **있는 값이거나 NULL** | 수강 표에 학생 표에 없는 학번 S9가 들어감 |
| **도메인 무결성** | 속성 값은 정해진 도메인 안의 값 | 학년 열(1~4)에 7을 넣음 |
| **사용자 정의 무결성** | 업무 규칙(트리거 등으로 구현) | "주문 수량은 재고보다 클 수 없다" |

참조되는 행을 지우거나 바꿀 때 어떻게 할지는 외래키에 옵션으로 정해요.

| 옵션(ON DELETE / ON UPDATE) | 동작 |
|---|---|
| NO ACTION(RESTRICT) | 참조하는 행이 있으면 거부 |
| CASCADE | 참조하는 행도 같이 삭제·변경 |
| SET NULL | 참조하는 쪽 외래키를 NULL로 |
| SET DEFAULT | 참조하는 쪽 외래키를 기본값으로 |

### 관계 대수 연산과 기호

**관계 대수**(relational algebra)는 "어떤 순서로 계산해 결과를 얻는지"를 적는 **절차적** 언어예요. 입력도 릴레이션, 결과도 릴레이션이에요(**폐쇄 특성**).

| 분류 | 연산 | 기호 | 하는 일 |
|---|---|---|---|
| 일반 집합 연산 | 합집합 | ∪ | 두 표의 행을 합침(중복은 한 번) |
| | 교집합 | ∩ | 두 표에 모두 있는 행 |
| | 차집합 | − | 앞 표에만 있는 행 |
| | 카티션 프로덕트 | × | 모든 행끼리 짝지음 |
| 순수 관계 연산 | 셀렉트 | σ(시그마) | 조건에 맞는 **행**만(수평 부분집합) |
| | 프로젝트 | π(파이) | 고른 **열**만(수직 부분집합), 중복 행 제거 |
| | 조인 | ⋈ | 공통 속성 값이 같은 행끼리 연결 |
| | 디비전 | ÷ | 나누는 표의 **모든** 행과 관련 있는 행 |

∪·∩·−는 두 표가 **합병 가능**(union-compatible)해야 써요. 차수가 같고, 같은 자리 속성의 도메인이 같아야 한다는 뜻이에요.

### 연산 결과의 크기

R의 차수를 dR·카디널리티를 cR, S는 dS·cS라고 할게요.

| 연산 | 결과 차수 | 결과 카디널리티 | 교환 법칙 |
|---|---|---|---|
| R ∪ S | dR(= dS) | cR + cS **이하** | 성립 |
| R ∩ S | dR(= dS) | cR, cS 중 작은 값 **이하** | 성립 |
| R − S | dR | cR **이하** | **불성립** |
| R × S | dR **+** dS | cR **×** cS | 성립 |
| σ(R) | dR | cR 이하 | σ끼리는 순서 바꿔도 같음 |
| π(R) | 고른 열 수 | cR 이하(중복 제거) | |

## 단계별 계산

예제 표 두 개로 연산을 하나씩 해 볼게요.

**학생**(차수 4, 카디널리티 4)

| 학번 | 이름 | 학과 | 학년 |
|---|---|---|---|
| S1 | 김 | 컴공 | 3 |
| S2 | 이 | 경영 | 2 |
| S3 | 박 | 컴공 | 1 |
| S4 | 최 | 수학 | 3 |

**수강**(차수 2, 카디널리티 6)과 **과목**(차수 1, 카디널리티 2)

| 학번 | 과목 |
|---|---|
| S1 | DB |
| S1 | OS |
| S2 | DB |
| S3 | DB |
| S3 | OS |
| S3 | NW |

| 과목 |
|---|
| DB |
| OS |

### 예제 1: σ → π → ⋈ 이어 쓰기

질의: "컴공 학생의 학번·이름과 수강 과목"

1. **σ**학과='컴공'(학생): 컴공인 행만 남겨요 → S1 김, S3 박. **4행 → 2행**, 열은 그대로 4개.
2. **π**학번,이름(1번 결과): 학번·이름 열만 남겨요 → (S1, 김), (S3, 박). **4열 → 2열**.
3. 2번 결과 **⋈** 수강: 학번이 같은 행끼리 이어 붙여요. 공통 속성 학번은 한 번만 나와요.

| 학번 | 이름 | 과목 |
|---|---|---|
| S1 | 김 | DB |
| S1 | 김 | OS |
| S3 | 박 | DB |
| S3 | 박 | OS |
| S3 | 박 | NW |

결과는 5행, 3열이에요. 조인 전에 σ·π로 표를 먼저 줄여 두면 이어 붙일 행이 적어져요.

### 예제 2: π는 중복을 없앤다

π학과(학생) → 컴공, 경영, 수학. 컴공이 두 번 있었지만 결과는 **3행**이에요(4행 아님). 결과도 릴레이션이라 같은 투플이 둘 있을 수 없기 때문이에요.

### 예제 3: 집합 연산

A = 학번 \{S1, S2, S3\}, B = 학번 \{S3, S4\}라고 할게요.

| 연산 | 결과 | 행 수 |
|---|---|---|
| A ∪ B | S1, S2, S3, S4 | 4 (3 + 2 = 5가 아님, S3 중복) |
| A ∩ B | S3 | 1 |
| A − B | S1, S2 | 2 |
| B − A | S4 | 1 (A − B와 다름 → 교환 불성립) |

### 예제 4: 카티션 프로덕트와 조인

- (학번 2행짜리 표) × 과목(2행) → 2 × 2 = **4행**, 차수 1 + 1 = **2**.
- 학생 ⋈ 수강 → 수강 6행마다 학생 정보가 붙어 **6행**, 차수 4 + 2 − 1 = **5**(공통 속성 학번 한 번만).

### 예제 5: 디비전 ÷

질의: "과목 표에 있는 과목(DB, OS)을 **모두** 들은 학생"

1. 수강을 학번별로 묶어요.
2. 학번마다 들은 과목 집합을 만들어요: S1 = \{DB, OS\}, S2 = \{DB\}, S3 = \{DB, OS, NW\}.
3. \{DB, OS\}를 전부 포함하는지 확인해요. S2는 OS가 없어서 탈락. S3는 NW를 더 들었지만 DB·OS가 다 있으니 통과.
4. 결과: 수강 ÷ 과목 = **S1, S3**. 결과에는 나누는 쪽 속성(과목)이 빠지고 학번만 남아요.

### 심화: 조인의 종류와 확장 연산

| 연산 | 기호 | 특징 |
|---|---|---|
| 세타 조인 | ⋈θ | =, ≠, &lt;, ≤, &gt;, ≥ 중 하나로 비교. 차수 = 두 차수의 합 |
| 동등 조인 | ⋈= | θ가 "="인 세타 조인. 공통 속성이 **두 번** 나와요 |
| 자연 조인 | ⋈ | 동등 조인에서 공통 속성을 **한 번만** 남김 |
| 세미 조인 | ⋉ | 조인한 뒤 한쪽(R) 속성만 남김. 교환 불성립 |
| 외부 조인 | ⟗ 등 | 짝이 없는 행도 NULL을 채워 결과에 포함 |

- SQL의 JOIN 종류는 [SQL 기초와 JOIN](../../../db/sql-basics-join/)에서 실제 쿼리로 볼 수 있어요.
- 디비전은 SQL에 바로 대응하는 문법이 없어서 `NOT EXISTS`를 두 번 쓰거나 `GROUP BY ... HAVING COUNT(...)`로 표현해요.

### 심화: 재명명 ρ와 기본 연산 (표준 교재 보충)

국내 수험서의 8개 연산 목록에는 없지만, Elmasri·Silberschatz 같은 표준 교재는 **재명명 ρ**(rho, 릴레이션·속성 이름 바꾸기)를 기본 연산에 넣어요. 기본 연산은 σ, π, ∪, −, ×, ρ이고, ∩·⋈·÷는 이 연산들을 조합해 만들 수 있어요.

### 관계 해석 개요

| 구분 | 관계 대수 | 관계 해석(relational calculus) |
|---|---|---|
| 성격 | **절차적**: 어떻게(순서) 구할지 | **비절차적**: 무엇을 원하는지만 |
| 기반 | 집합 연산 + 관계 연산 | 수학의 프레디킷 해석(술어 논리) |
| 종류 | | 투플 관계 해석, 도메인 관계 해석 |

- 둘은 **표현력이 같아요**. 이 둘로 표현할 수 있는 질의를 모두 표현할 수 있는 언어를 "관계적으로 완전하다"고 해요.
- SQL은 관계 해석에 바탕을 둔 비절차적 언어예요.

## 객관식 함정

| 이렇게 나오면 틀린 보기 | 맞는 내용 |
|---|---|
| 카디널리티는 속성의 수다 | 카디널리티 = **투플(행)** 수, 차수 = 속성(열) 수 |
| 릴레이션 스키마는 외연이며 동적이다 | 스키마 = **내포·정적**, 인스턴스 = 외연·동적 |
| 릴레이션의 투플은 순서를 가진다 | 투플·속성 모두 **순서 없음** |
| 슈퍼키는 유일성과 최소성을 만족한다 | 슈퍼키는 **유일성만**. 둘 다 만족하면 후보키 |
| 외래키에 NULL이 있으면 참조 무결성 위반 | 외래키 NULL은 **허용**. 기본키 NULL이 개체 무결성 위반 |
| 외래키와 참조되는 기본키는 이름이 같아야 한다 | 이름은 달라도 됨, **도메인**이 같아야 함 |
| 신입 사번이 기존 사번과 같으면 안 되는 건 원자성(1NF) 규칙 | **개체 무결성**(기본키 중복 불가) |
| 대체키(UNIQUE)는 기본키처럼 NULL 불가 | UNIQUE는 NULL **허용** |
| σ는 열을, π는 행을 고른다 | σ = **행(수평)**, π = **열(수직)** |
| SQL의 SELECT 절은 σ에 해당 | SELECT 절 = **π**, WHERE 절 = **σ** |
| 관계 대수는 비절차적 언어다 | 관계 대수 = **절차적**, 관계 해석 = 비절차적 |
| R × S의 차수는 두 차수의 곱 | 차수는 **합**, 카디널리티가 **곱** |
| 차집합은 교환 법칙이 성립한다 | R − S ≠ S − R |
| π 결과는 원래 행 수와 같다 | 관계 대수 π는 **중복 제거**. (SQL SELECT는 DISTINCT 없으면 중복 유지) |
| 디비전 결과에 나누는 쪽 속성도 남는다 | 나누는 쪽 속성은 **빠짐** |

## 연습 문제

<details>
<summary>1. 속성이 5개, 투플이 7개인 릴레이션의 차수와 카디널리티는?</summary>

① 차수 7, 카디널리티 5 ② 차수 5, 카디널리티 7 ③ 차수 5, 카디널리티 35 ④ 차수 12, 카디널리티 7

**정답: ②**

차수는 속성(열) 개수 5, 카디널리티는 투플(행) 개수 7이에요. 두 수를 곱하거나 더할 일은 없어요.
</details>

<details>
<summary>2. 릴레이션의 특성으로 옳지 않은 것은?</summary>

① 한 릴레이션에 똑같은 투플이 두 개 있을 수 없다.

② 투플은 입력된 순서대로 의미를 가진다.

③ 속성의 순서는 바뀌어도 같은 릴레이션이다.

④ 각 속성 값은 더 나눌 수 없는 원자값이다.

**정답: ②**

투플에는 순서가 없어요. 행을 어떤 순서로 보여 주든 같은 릴레이션이에요. 나머지는 유일성·속성 무순서·원자성으로 맞는 설명이에요.
</details>

<details>
<summary>3. 무결성 제약조건에 대한 설명으로 옳은 것은?</summary>

① 외래키 값이 NULL이면 참조 무결성 위반이다.

② 기본키를 이루는 속성 중 하나라도 NULL이면 개체 무결성 위반이다.

③ 학년 열(1~4)에 7을 넣는 것은 참조 무결성 위반이다.

④ 외래키는 참조하는 기본키와 속성 이름이 반드시 같아야 한다.

**정답: ②**

① 외래키 NULL은 허용돼요. ③ 정해진 값 범위를 벗어난 건 도메인 무결성 위반이에요. ④ 이름은 달라도 되고 도메인만 같으면 돼요.
</details>

<details>
<summary>4. SQL 문장의 WHERE 절이 하는 일과 가장 가까운 관계 대수 연산은?</summary>

① π ② σ ③ × ④ ÷

**정답: ②**

WHERE는 조건에 맞는 행만 남기니 셀렉트 σ예요. SQL의 SELECT 절(열 고르기)이 오히려 프로젝트 π에 해당해서, 이름 때문에 거꾸로 고르기 쉬워요.
</details>

<details>
<summary>5. 차수 3·카디널리티 4인 릴레이션 R과 차수 2·카디널리티 5인 릴레이션 S가 있다. R × S의 차수와 카디널리티는?</summary>

① 차수 6, 카디널리티 9 ② 차수 5, 카디널리티 9 ③ 차수 5, 카디널리티 20 ④ 차수 6, 카디널리티 20

**정답: ③**

카티션 프로덕트는 열은 이어 붙이니 차수 3 + 2 = 5, 행은 모든 짝을 만드니 카디널리티 4 × 5 = 20이에요.
</details>

<details>
<summary>6. 위 "단계별 계산"의 학생 표(학과: 컴공, 경영, 컴공, 수학)에 π학과를 적용한 결과의 카디널리티는?</summary>

① 1 ② 2 ③ 3 ④ 4

**정답: ③**

관계 대수의 π는 결과에서 중복 투플을 없애요. 컴공·경영·수학 3행이 남아요. SQL에서 `SELECT 학과 FROM 학생`은 DISTINCT가 없으면 4행이 나온다는 점과 구별하세요.
</details>

<details>
<summary>7. 릴레이션 R(A, B, C)의 투플이 (1, a, x), (1, b, x), (2, a, y), (3, a, x)일 때 후보키는?</summary>

① A ② (A, B) ③ (A, C) ④ (A, B, C)

**정답: ②**

- 단일 속성: A는 1이 두 번, B는 a가 세 번, C는 x가 세 번 → 모두 탈락.
- (A, B): (1,a) (1,b) (2,a) (3,a) 모두 다름 → 유일.
- (A, C): (1,x)가 두 번 → 탈락. (B, C): (a,x)가 두 번 → 탈락.
- (A, B, C)도 유일하지만 C를 빼도 유일하니 최소성 위반 → 슈퍼키일 뿐이에요.

그래서 후보키는 (A, B) 하나예요.
</details>

<details>
<summary>8. 수강(학번, 과목) = (S1,DB) (S2,DB) (S2,OS) (S2,NW) (S3,OS) (S4,DB) (S4,OS), 과목(과목) = DB, OS일 때 수강 ÷ 과목의 결과는?</summary>

① S2 ② S1, S4 ③ S2, S4 ④ S1, S2, S3, S4

**정답: ③**

학번별 과목 집합은 S1 = \{DB\}, S2 = \{DB, OS, NW\}, S3 = \{OS\}, S4 = \{DB, OS\}예요. DB와 OS를 **모두** 포함하는 건 S2와 S4예요. S2가 NW를 더 들은 건 상관없어요.
</details>

## 면접 질문

<details>
<summary>Q. 슈퍼키, 후보키, 기본키의 차이를 설명해 주세요.</summary>

**답변(30초)** 셋 다 행을 유일하게 구별하는 속성 집합이에요. 슈퍼키는 유일성만 만족하면 되고, 후보키는 거기에 최소성까지 만족해서 속성을 하나라도 빼면 유일성이 깨져요. 기본키는 후보키 중 대표로 고른 하나이고 NULL이 될 수 없어요. 남은 후보키는 대체키라고 불러요.

**꼬리질문**
- Q. 외래키에 NULL이 들어가도 되나요? → 돼요. 참조 무결성은 "없는 값을 가리키지 말라"는 규칙이라 NULL(아직 참조 없음)은 위반이 아니에요. NOT NULL로 막을지는 업무 규칙에 따라 정해요.
- Q. 참조되는 행을 지우면 어떻게 되나요? → 외래키 옵션에 따라 거부(NO ACTION), 같이 삭제(CASCADE), NULL로 바꿈(SET NULL) 중 하나가 일어나요.
</details>
