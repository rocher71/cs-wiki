:::tip[한 줄 요약]
디스크 **접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간**이고, 디스크 스케줄링은 그중 가장 큰 **탐색 시간(헤드 이동 거리)**을 줄이려는 규칙이에요. 계산 문제는 처리 순서를 적고 **이웃한 트랙 번호 차이를 모두 더하면** 끝나요. 단, SCAN은 끝 트랙까지 가는지, C-SCAN·C-LOOK은 되돌아가는 점프를 거리에 넣는지 문제 조건을 꼭 확인하세요.
:::

:::note[처음이라면 여기까지]
① 하드디스크는 레코드판처럼 돌아가는 원판 위를 바늘(헤드)이 오가며 읽어요. 바늘을 옮기는 시간이 가장 오래 걸려요.

② 그래서 요청이 여러 개 쌓이면 "어떤 순서로 가야 바늘이 덜 움직이나"를 정해요. 이게 디스크 스케줄링이에요.

③ SSTF는 가장 가까운 곳부터, SCAN은 엘리베이터처럼 한 방향으로 쭉, LOOK은 SCAN인데 끝까지 안 가고 마지막 요청에서 돌아서요.

④ 아래 "단계별 계산"을 손으로 따라 하고 연습 문제 1~4번을 풀어 보세요. RAID는 0·1·5 세 줄만 먼저 외우세요.
:::

## 쉽게 이해하기

200층짜리 건물에 엘리베이터가 한 대 있어요. 지금 60층에 있고, 95층·180층·34층… 여러 층에서 호출이 들어와 있어요. 엘리베이터가 움직인 층수를 줄이고 싶어요.

호출 순서대로 가면(FCFS) 위아래로 왔다 갔다 하느라 많이 움직여요. 가장 가까운 층부터 가면(SSTF) 덜 움직이지만, 꼭대기 근처 손님은 계속 밀릴 수 있어요. 한 방향으로 끝까지 올라가며 태우고, 다시 내려오며 태우면(SCAN) 누구도 끝없이 밀리지 않아요.

엘리베이터가 디스크 헤드, 층이 **트랙**(원판 위 동심원 하나), 호출이 읽기·쓰기 요청이에요.

단, 실제 디스크는 층(트랙)에 도착한 뒤에도 원판이 돌아 원하는 자리가 헤드 밑에 올 때까지 또 기다려야 해요. 이 시간이 회전 지연이에요.

## 제대로 알기

### 디스크 구조

| 용어 | 뜻 |
|---|---|
| **트랙**(track) | 원판 표면의 동심원 하나 |
| **섹터**(sector) | 트랙을 부채꼴로 나눈 고정 크기 칸. 데이터를 읽고 쓰는 기본 단위(전통적으로 512바이트) |
| **실린더**(cylinder) | 여러 장의 원판에서 같은 위치에 있는 트랙들의 묶음. 헤드를 안 옮기고 한 번에 접근 가능 |
| **헤드**(head)·암(arm) | 데이터를 읽는 바늘과 그걸 움직이는 팔 |

### 접근 시간 3요소

| 요소 | 뜻 | 포인트 |
|---|---|---|
| **탐색 시간**(seek time) | 헤드를 목표 트랙으로 옮기는 시간 | 보통 셋 중 가장 큼. 디스크 스케줄링이 줄이려는 대상 |
| **회전 지연**(rotational latency) | 트랙에 온 뒤 원하는 섹터가 헤드 밑으로 돌아올 때까지 | **평균 = 1회전 시간의 절반** |
| **전송 시간**(transfer time) | 실제로 데이터를 읽어 메모리로 옮기는 시간 | 보통 가장 작음 |

- **고정 헤드** 디스크는 트랙마다 헤드가 따로 있어서 **탐색 시간이 없어요**. 접근 시간 = 회전 지연 + 전송 시간.
- 스케줄링이 좋은지는 처리량(많이), 평균 응답 시간(짧게), **응답 시간 편차**(작게)로 따져요. 편차가 크면 어떤 요청은 유난히 오래 기다린다는 뜻이에요.

접근 시간 계산 예를 하나 볼게요. 6,000 RPM(분당 6,000바퀴), 평균 탐색 4ms, 트랙당 200섹터, 섹터 1개를 읽어요.

1. 1회전 시간 = 60,000ms ÷ 6,000 = **10ms**
2. 평균 회전 지연 = 10 ÷ 2 = **5ms**
3. 섹터 1개 전송 = 10 ÷ 200 = **0.05ms** (한 바퀴에 200섹터가 지나가니까)
4. 접근 시간 = 4 + 5 + 0.05 = **9.05ms** (고정 헤드라면 탐색 0이라 5.05ms)

### 스케줄링 알고리즘 한눈에

| 기법 | 규칙 | 기아 | 특징 |
|---|---|---|---|
| **FCFS** | 요청이 온 순서대로 | 없음 | 공평하고 단순. 요청이 흩어져 있으면 이동 거리가 큼. 부하가 적을 때 적합 |
| **SSTF** | 지금 헤드에서 **가장 가까운** 요청부터 | **있음** | 평균 이동이 짧고 처리량이 높음. 양 끝 요청이 밀리고 응답 편차가 커서 대화형엔 부적합 |
| **SCAN**(엘리베이터) | 한 방향으로 가며 처리, **디스크 끝까지** 간 뒤 방향을 바꿈 | 없음 | SSTF의 기아를 해결 |
| **C-SCAN** | 한 방향으로만 처리. 끝에 닿으면 **반대쪽 끝으로 점프**한 뒤 같은 방향으로 다시 처리 | 없음 | 점프하는 동안은 처리 안 함. 안쪽·바깥쪽 차별이 줄어 응답 편차가 작음 |
| **LOOK** | SCAN과 같되 끝까지 안 가고 **그 방향 마지막 요청**에서 돌아섬 | 없음 | SCAN의 쓸데없는 끝 이동을 없앰 |
| **C-LOOK** | C-SCAN과 같되 끝까지 안 가고, 마지막 요청에서 **반대쪽 가장 먼 요청**으로 점프 | 없음 | C-SCAN의 끝 이동을 없앰 |

이름에 "C"(circular, 원형)가 붙으면 **한 방향으로만 처리**한다는 뜻이에요.

### 그 밖의 기법

| 기법 | 기준 | 포인트 |
|---|---|---|
| **N-step SCAN** | SCAN인데, 출발할 때 기다리던 요청만 처리하고 가는 도중 온 요청은 다음 번에 | 한 트랙에 요청이 몰려도 다른 요청이 무한정 밀리지 않음 |
| **SLTF**(섹터 큐잉) | **회전 지연**이 가장 짧은 요청부터 | 탐색이 없는 고정 헤드 디스크에 효과적 |
| **SPTF** | 탐색 시간 + 회전 지연 합이 가장 짧은 요청부터 | 기아 있음 |
| **에센바흐**(Eschenbach) | C-SCAN처럼 가되, 한 트랙에서는 한 바퀴 동안 처리하도록 요청을 재배열 | 탐색과 회전 지연을 함께 줄이려는 방식 |

### RAID

**RAID**(Redundant Array of Independent Disks)는 디스크 여러 개를 묶어 하나처럼 쓰면서 속도나 안정성을 높이는 방법이에요. 두 가지 기술이 핵심이에요.

- **스트라이핑**(striping): 데이터를 조각내서 여러 디스크에 나눠 씀 → 동시에 읽고 써서 빠름
- **미러링**(mirroring): 같은 데이터를 두 디스크에 똑같이 씀 → 하나가 고장 나도 안전

| 레벨 | 방식 | 견디는 고장 | 용량 효율(디스크 N개) | 한 줄 정리 |
|---|---|---|---|---|
| **RAID 0** | 스트라이핑만 | **0개**(하나만 고장 나도 전체 손실) | 100% | 가장 빠르지만 중복이 없음 |
| **RAID 1** | 미러링 | 쌍 중 1개 | 50% | 가장 단순한 안전장치. 읽기는 두 디스크에서 나눠 가능 |
| **RAID 5** | 블록 스트라이핑 + **패리티를 모든 디스크에 분산** | **1개** | (N−1)/N | 최소 3개. 쓰기마다 패리티 갱신 비용 |

출처: 『정처기-컴퓨터일반』 운영체제 편에는 RAID 본문이 없어서, 위 표는 표준 OS 교재(Silberschatz)와 RAID 원 논문(Patterson·Gibson·Katz, 1988)을 기준으로 정리했어요.

나머지 레벨은 한 줄씩만 알아 두세요.

| 레벨 | 내용 |
|---|---|
| RAID 2 | 해밍 코드로 비트 단위 오류 정정. 지금은 거의 안 씀 |
| RAID 3 | 바이트 단위 스트라이핑 + **전용 패리티 디스크** 하나 |
| RAID 4 | **블록** 단위 스트라이핑 + 전용 패리티 디스크 하나. 쓸 때마다 패리티 디스크가 병목 |
| RAID 6 | 패리티 2개를 분산. 디스크 **2개**까지 고장 견딤, 최소 4개 |
| RAID 10(1+0) | 미러 쌍을 만들고 그 쌍들을 스트라이핑. DB 서버에서 자주 씀 |

**패리티**(parity)는 XOR(두 비트가 다르면 1)로 만든 검사용 값이에요. 디스크 3개에 A1 = 1010, A2 = 0110, A3 = 1100이 있으면 패리티는 1010 ⊕ 0110 ⊕ 1100 = 0000이에요. A1이 든 디스크가 고장 나면 A2 ⊕ A3 ⊕ 패리티 = 0110 ⊕ 1100 ⊕ 0000 = 1010으로 A1을 되살려요.

RAID 4와 5의 차이는 패리티를 어디에 두느냐예요. 4는 한 디스크에 몰고, 5는 줄마다 다른 디스크에 돌려 가며 둬요.

| 줄 | 디스크 0 | 디스크 1 | 디스크 2 | 디스크 3 |
|---|---|---|---|---|
| 0 | A1 | A2 | A3 | **A패리티** |
| 1 | B1 | B2 | **B패리티** | B3 |
| 2 | C1 | **C패리티** | C2 | C3 |
| 3 | **D패리티** | D1 | D2 | D3 |

RAID는 **백업이 아니에요**. 실수로 지운 파일이나 랜섬웨어로 망가진 파일은 모든 디스크에 똑같이 반영돼요.

### 파일 할당 방식

파일을 디스크 블록에 어떻게 놓을지 정하는 방법이에요. 단편화 개념은 [메모리 관리와 페이지 교체](../memory/)에서 본 것과 같아요.

| 방식 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| **연속 할당** | 파일을 이어진 블록에 통째로. 디렉터리엔 시작 블록과 길이만 | 순차·직접 접근 모두 빠름, 헤드 이동 적음 | **외부 단편화**, 파일 크기를 늘리기 어려움 |
| **연결 할당** | 블록마다 다음 블록 위치(포인터)를 적어 둠 | 외부 단편화 없음, 크기 늘리기 쉬움 | **직접 접근이 느림**(처음부터 따라가야 함), 포인터 하나 깨지면 뒤가 유실 |
| **색인 할당** | 파일마다 **색인 블록**에 블록 주소 목록을 모아 둠 | 직접 접근 가능, 외부 단편화 없음 | 작은 파일도 색인 블록 하나를 차지 |

- 연결 할당의 포인터를 블록에서 꺼내 표 하나로 모은 게 **FAT**(File Allocation Table)예요.
- 색인 할당의 대표가 유닉스 **i-node**예요. 직접 블록 주소 몇 개 + 단일·이중·삼중 간접 블록으로 큰 파일도 표현해요.
- 연결·색인 파일은 블록이 디스크 곳곳에 흩어져 있어서 헤드 이동이 길어져요.

### 심화: SSD에서는 왜 디스크 스케줄링이 덜 중요한가

SSD에는 움직이는 헤드도, 도는 원판도 없어요. 그래서 탐색 시간과 회전 지연이 사실상 없고, 요청 순서를 바꿔서 얻는 이득이 작아요. 리눅스도 SSD에는 순서를 거의 안 바꾸는 단순한 I/O 스케줄러를 쓰는 경우가 많아요.

반대로 HDD 시절의 DB는 랜덤 쓰기를 피하려고 변경 내용을 로그 파일 끝에 **순서대로 이어 쓰는** 방식(redo log, WAL)을 썼어요. 순차 쓰기는 헤드가 거의 안 움직여서 빠르기 때문이에요.

## 단계별 계산

### 문제 조건

- 트랙 0 ~ 199, 헤드는 지금 **60**, **큰 번호 방향**으로 움직이는 중
- 요청 큐(온 순서): **95, 180, 34, 119, 11, 123, 62, 64**

푸는 순서는 언제나 같아요.

1. 규칙대로 **처리 순서**를 적어요.
2. 이웃한 두 트랙의 **차이**를 구해요.
3. 모두 더해요.

방향이 한쪽으로 쭉 가는 구간은 "끝 − 시작" 한 번으로 계산하면 빨라요.

### FCFS

온 순서 그대로 가요.

| 이동 | 거리 |
|---|---|
| 60 → 95 | 35 |
| 95 → 180 | 85 |
| 180 → 34 | 146 |
| 34 → 119 | 85 |
| 119 → 11 | 108 |
| 11 → 123 | 112 |
| 123 → 62 | 61 |
| 62 → 64 | 2 |

총 이동 = **634**

### SSTF

매번 "지금 위치에서 가장 가까운 남은 요청"을 골라요.

| 현재 | 후보 중 가장 가까운 것 | 거리 |
|---|---|---|
| 60 | 62 | 2 |
| 62 | 64 | 2 |
| 64 | **34**(30) vs 95(31) → 34 | 30 |
| 34 | 11 | 23 |
| 11 | 95 | 84 |
| 95 | 119 | 24 |
| 119 | 123 | 4 |
| 123 | 180 | 57 |

총 이동 = **226**

64에서 위쪽 95보다 아래쪽 34가 1 더 가까워서 방향을 꺾었어요. SSTF는 "지금 어느 방향으로 가던 중인지"를 신경 쓰지 않아요.

### SCAN (끝 트랙까지)

큰 번호 방향으로 62, 64, 95, 119, 123, 180을 처리하고, 요청이 없어도 **끝 트랙 199까지** 간 뒤 돌아와 34, 11을 처리해요.

```text
60 → 62 → 64 → 95 → 119 → 123 → 180 → 199 → 34 → 11
```

- 올라가는 구간: 199 − 60 = 139
- 내려오는 구간: 199 − 11 = 188
- 총 이동 = 139 + 188 = **327**

### LOOK

SCAN과 같은데 199까지 안 가고 마지막 요청 180에서 바로 돌아서요.

```text
60 → 62 → 64 → 95 → 119 → 123 → 180 → 34 → 11
```

- 180 − 60 = 120
- 180 − 11 = 169
- 총 이동 = 120 + 169 = **289**

### C-SCAN

큰 번호 방향으로만 처리해요. 199까지 간 뒤 **0으로 점프**하고, 다시 큰 번호 방향으로 11, 34를 처리해요.

```text
60 → 62 → 64 → 95 → 119 → 123 → 180 → 199 ⇒ 0 → 11 → 34
```

- 199 − 60 = 139
- 점프 199 → 0 = 199
- 34 − 0 = 34
- 총 이동 = 139 + 199 + 34 = **372** (점프를 빼면 173)

### C-LOOK

C-SCAN과 같되 끝까지 안 가요. 180에서 반대쪽 가장 먼 요청 **11로 점프**한 뒤 34를 처리해요.

```text
60 → 62 → 64 → 95 → 119 → 123 → 180 ⇒ 11 → 34
```

- 180 − 60 = 120
- 점프 180 → 11 = 169
- 34 − 11 = 23
- 총 이동 = 120 + 169 + 23 = **312** (점프를 빼면 143)

### 비교

| 알고리즘 | 총 이동 | 점프 뺀 값 |
|---|---|---|
| SSTF | **226** | |
| LOOK | 289 | |
| C-LOOK | 312 | 143 |
| SCAN | 327 | |
| C-SCAN | 372 | 173 |
| FCFS | 634 | |

같은 큐에서 헤드가 **작은 번호 방향**으로 가던 중이었다면 SCAN 240, LOOK 218, C-SCAN 396(점프 빼면 197), C-LOOK 336(점프 빼면 167)이 돼요. FCFS와 SSTF는 방향과 상관없어서 그대로 634, 226이에요. 방향 조건 하나로 답이 바뀌니 문제를 꼭 다시 읽으세요.

### 문제에서 꼭 확인할 조건

| 확인할 것 | 왜 |
|---|---|
| 처음 이동 **방향** | SCAN·LOOK·C 계열은 방향에 따라 처리 순서가 완전히 달라짐 |
| **트랙 범위**(0 ~ 199 등) | 교재 정의상 SCAN·C-SCAN은 끝 트랙까지 감. 범위가 안 주어지면 끝까지 갈 수 없으니 LOOK처럼 계산하라는 뜻일 수 있음 |
| 점프 거리 **포함 여부** | C-SCAN·C-LOOK의 되돌아가는 이동을 넣는 문제도, 빼는 문제도 있음. 『정처기-컴퓨터일반』 교재의 기출 풀이는 **포함**해서 계산. 보기 숫자를 두 방식으로 모두 맞춰 보세요 |
| SSTF **동점** | 양쪽 거리가 같으면 문제에 적힌 규칙을 따름 |

## 객관식 함정

| 이렇게 나오면 틀린 보기 | 맞는 내용 |
|---|---|
| 접근 시간 = 탐색 시간 + 대기 시간 + 처리 시간 | **탐색 + 회전 지연 + 전송** |
| 고정 헤드 디스크에도 탐색 시간이 있다 | 트랙마다 헤드가 있어 탐색 **없음** |
| 평균 회전 지연은 1회전 시간과 같다 | 1회전의 **절반** |
| 디스크 스케줄링은 주로 전송 시간을 줄인다 | 주로 **탐색 시간** |
| SSTF는 기아가 없다 | 양 끝 요청이 밀리는 **기아 있음**, 응답 편차도 큼 |
| SSTF는 대화형 시스템에 적합하다 | 응답 편차가 커서 **부적합** |
| LOOK은 디스크 끝 트랙까지 간 뒤 방향을 바꾼다 | 그건 **SCAN**. LOOK은 마지막 요청에서 돌아섬 |
| C-SCAN은 되돌아가는 동안에도 요청을 처리한다 | 되돌아가는 동안은 처리 **안 함** |
| SLTF는 탐색 시간이 가장 짧은 요청부터 처리한다 | **회전 지연** 기준. 탐색 기준은 SSTF |
| RAID 0은 미러링, RAID 1은 스트라이핑 | 반대. **0 = 스트라이핑**, **1 = 미러링** |
| RAID 0은 디스크 하나가 고장 나도 복구된다 | 중복이 없어 **전체 손실** |
| RAID 5는 디스크 2개 동시 고장을 견딘다 | **1개**. 2개는 RAID 6 |
| RAID 5는 패리티를 전용 디스크 하나에 둔다 | 그건 RAID 3·4. 5는 **분산** |
| 연속 할당은 내부 단편화가 생긴다 | **외부 단편화** |
| 연결 할당은 직접(임의) 접근이 빠르다 | 처음부터 따라가야 해서 **느림** |

## 연습 문제

<details>
<summary>1. 이동 헤드 디스크의 접근 시간을 구성하는 요소가 아닌 것은?</summary>

① 탐색 시간 ② 회전 지연 시간 ③ 전송 시간 ④ 문맥 교환 시간

**정답: ④**

디스크 접근 시간은 탐색 + 회전 지연 + 전송이에요. 문맥 교환은 CPU가 프로세스를 바꿀 때 드는 시간이라 디스크와 관계없어요.
</details>

<details>
<summary>2. 파일 할당 방식에 대한 설명으로 옳은 것은?</summary>

① 연속 할당은 외부 단편화가 생기지 않는다.

② 연결 할당은 파일의 중간 블록을 바로 찾아갈 수 있어 직접 접근이 빠르다.

③ 색인 할당은 블록 주소를 색인 블록에 모아 두므로 직접 접근이 가능하다.

④ 유닉스의 i-node는 연결 할당의 대표적인 예이다.

**정답: ③**

① 연속 할당은 외부 단편화가 생겨요. ② 연결 할당은 포인터를 처음부터 따라가야 해서 직접 접근이 느려요. ④ i-node는 색인 할당이에요.
</details>

<details>
<summary>3. RAID에 대한 설명으로 옳은 것은?</summary>

① RAID 0은 미러링으로 디스크 하나가 고장 나도 데이터를 지킨다.

② RAID 1은 같은 데이터를 두 디스크에 저장해 용량 효율이 50%이다.

③ RAID 5는 패리티를 전용 디스크 하나에 모아 두어 쓰기 병목이 생긴다.

④ RAID 5는 디스크 2개가 동시에 고장 나도 복구할 수 있다.

**정답: ②**

① RAID 0은 스트라이핑이고 중복이 없어요. ③ 전용 패리티 디스크 병목은 RAID 4 이야기예요. 5는 패리티를 분산해요. ④ RAID 5는 1개까지, 2개는 RAID 6이에요.
</details>

<details>
<summary>4. 회전 속도 5,000 RPM, 평균 탐색 시간 6ms, 트랙당 100섹터인 디스크에서 섹터 1개를 읽는 평균 접근 시간은?</summary>

① 6.12ms ② 12.0ms ③ 12.12ms ④ 18.12ms

**정답: ③**

- 1회전 = 60,000 ÷ 5,000 = 12ms
- 평균 회전 지연 = 12 ÷ 2 = 6ms
- 섹터 1개 전송 = 12 ÷ 100 = 0.12ms
- 접근 시간 = 6 + 6 + 0.12 = **12.12ms**

④ 18.12는 회전 지연을 1회전 전체(12ms)로 잘못 넣은 값이에요. ① 6.12는 탐색을 빠뜨린 값(고정 헤드라면 맞는 값)이에요.
</details>

<details>
<summary>5. 트랙 0 ~ 99, 헤드 위치 50, 요청 큐가 82, 17, 43, 61, 24, 90, 5일 때 SSTF의 총 헤드 이동 거리는?</summary>

① 125 ② 139 ③ 143 ④ 329

**정답: ②**

| 현재 | 가장 가까운 것 | 거리 |
|---|---|---|
| 50 | 43(7) vs 61(11) → 43 | 7 |
| 43 | 61(18) vs 24(19) → 61 | 18 |
| 61 | 82 | 21 |
| 82 | 90 | 8 |
| 90 | 24 | 66 |
| 24 | 17 | 7 |
| 17 | 5 | 12 |

총 = 7 + 18 + 21 + 8 + 66 + 7 + 12 = **139**

④ 329는 FCFS, ① 125는 큰 번호 방향 LOOK, ③ 143은 큰 번호 방향 SCAN 값이에요. 43에서 24 대신 61로 간 결정 때문에 나중에 90 → 24로 크게 돌아와서, 이 큐에서는 SSTF가 LOOK보다 더 많이 움직였어요. SSTF가 항상 최소는 아니에요.
</details>

<details>
<summary>6. 5번과 같은 조건에서 헤드가 큰 번호 방향으로 움직이는 중이다. C-LOOK의 총 이동 거리는? (되돌아가는 점프 거리도 포함)</summary>

① 78 ② 155 ③ 163 ④ 191

**정답: ③**

처리 순서: 50 → 61 → 82 → 90 ⇒ 5 → 17 → 24 → 43

- 90 − 50 = 40
- 점프 90 → 5 = 85
- 43 − 5 = 38
- 총 = 40 + 85 + 38 = **163**

① 78은 점프를 뺀 값이에요. ④ 191은 C-SCAN(99까지 갔다가 0으로 점프, 49 + 99 + 43) 값이에요. 문제에 "점프 포함" 조건이 없으면 보기에 163과 78 중 어느 쪽이 있는지 보고 판단하세요.
</details>

## 면접 질문

<details>
<summary>Q. HDD의 접근 시간은 무엇으로 구성되고, SSD는 왜 랜덤 읽기가 빠른가요?</summary>

**답변(30초)** HDD 접근 시간은 헤드를 트랙으로 옮기는 탐색 시간, 원하는 섹터가 돌아올 때까지의 회전 지연, 실제 데이터 전송 시간을 더한 거예요. 이 중 탐색과 회전 지연이 기계 동작이라 가장 오래 걸려요. 그래서 HDD는 흩어진 곳을 읽는 랜덤 I/O가 느리고, OS는 디스크 스케줄링으로 헤드 이동을 줄여요. SSD는 헤드도 원판도 없어서 탐색과 회전 지연이 사실상 없고, 그래서 랜덤 읽기가 HDD보다 훨씬 빨라요.

**꼬리질문**
- Q. DB가 변경 내용을 로그에 순서대로 먼저 쓰는 이유는? → 순차 쓰기는 헤드가 거의 안 움직여 빠르기 때문이에요. 실제 데이터 파일 반영은 나중에 몰아서 해요.
</details>

<details>
<summary>Q. RAID 0, 1, 5의 차이를 설명해 주세요.</summary>

**답변(30초)** RAID 0은 데이터를 여러 디스크에 나눠 쓰는 스트라이핑이라 빠르지만 중복이 없어서 하나만 고장 나도 전체를 잃어요. RAID 1은 같은 데이터를 두 디스크에 쓰는 미러링이라 안전하지만 용량은 절반만 써요. RAID 5는 스트라이핑에 패리티를 모든 디스크에 나눠 넣어서, 디스크 하나가 고장 나도 나머지로 복구하고 용량은 N−1개만큼 써요. 대신 쓸 때마다 패리티를 다시 계산하는 비용이 있어요.

**꼬리질문**
- Q. DB 서버에 RAID 5보다 RAID 10을 많이 쓰는 이유는? → 쓰기마다 패리티 계산이 없어 쓰기가 빠르고, 고장 난 디스크를 재구축할 때도 미러 하나만 복사하면 돼서 부담이 작아요.
</details>
